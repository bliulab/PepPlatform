# 管理员资源策略

后台提供「资源策略」「存储与清理」「公告」。用户可在模型库与账户页查看模型额度，在每个模型条目中保护模型、下载权重与配置。管理员可选择是否发布额度调整或清理公告，默认不推送。

## 欢迎自行部署

公共服务的存储与计算资源有限。如果具备相应资源，欢迎[自行部署 Web 服务](deployment.zh-CN.md)，自主配置用户、训练与推理额度、模型保留期限、公告和维护时间。

## 验证码邮件发送上限

「每日账号验证码邮件上限」默认 **20 封**，`0` 表示暂停发送，按 UTC 自然日统计，每天 UTC 00:00（北京时间 08:00）重置。注册验证、用户重发、找回密码和管理员重发共用额度；管理员不豁免。邮件预算与每日注册人数上限独立，先触发的限制先执行。这是平台自设上限，不代表邮箱服务商承诺的额度。

发信前在数据库短事务内原子预占一次，提交后才连接 SMTP。发送失败、超时和预占后进程退出均不返还，重启、删除账号或验证码不清零。未配置 SMTP 的开发验证码不占真实发信额度。首次启用从启用时开始统计，不倒推历史发信量；额度恢复后需重新请求，不积压邮件。

管理员通过资源策略的 `limits.daily_verification_email_limit` 修改非负整数上限，立即影响后续申请，已用量保留。`GET /api/admin/email-delivery-usage` 仅管理员可访问，返回日期、已用、上限、剩余和重置时间。耗尽时发信入口返回 HTTP 429，`quota_type=daily_verification_email_limit`，提供 `reset_at` 和 `Retry-After`；设为 0 时提示管理员暂停，不承诺次日恢复。注册被拦截时不创建账号、不消耗注册名额；重发被拦截时保留原有效验证码。已有有效验证码仍可验证，已有用户正常登录不受邮件预算影响。

公告开关统一标为「发布本次用户资源限制变更公告」，在途实验数、单次及累计训练时长等用户资源限制都由它控制，默认关闭。队列、磁盘保护和邮件上限等平台设置保存时只记录审计，不自动发布用户公告；清理公告独立选择。

迁移 `20261108_0017` 仅新增独立邮件计数表，兼容直接初始化；旧策略缺少邮件上限时默认 20。邮件策略与计数不进入实验配置、训练命令、接收快照或版本身份。

## 模型总数与保护数量

「模型保留总数上限」和「可保护模型数」是两个配置项。新部署默认可保留 **5 个模型，其中最多保护 3 个**。被保护模型包含在保留总数中；保护上限不能大于总数上限，后端对个人配置及全局变更后的有效配置统一校验。

模型额度**不会每日重置**。排队及运行中的训练、集成任务会占用模型名额；名额不足时，在计算开始前拒绝新增任务。模型发布成功后占位转为已保存模型，任务失败或取消后释放占位。删除模型或完成定期清理释放保留名额；无所属用户的平台模型不占个人名额。

管理员调低上限不会自动删除已有模型或撤销已有保护；页面显示超额状态，释放名额后才能新增。取消保护只释放保护额度，不会删除模型。需要长期留存权重时，请保护模型或在通知截止时间前自行下载备份。

## 配额继承与批量设置

- 管理员豁免个人次数、并发、时长、存储、文件和产物大小、模型及保护数量限制，页面显示「不限」，实际用量仍记录。平台磁盘、队列、GPU 调度、推理超时与模型来源规则继续生效；模型闲置清理仍由独立策略管理。管理员操作普通用户的资源时按资源所属用户计额。
- 未设置个人值的字段跟随全局默认；个人接口中 `null` 表示恢复继承，配额 `0` 表示禁用对应能力，保留天数至少为 1。
- 旧配额保留为个人设置，默认禁止全局覆盖。
- 管理员可在用户详情中设置「允许全局配置覆盖个人设置」；普通用户不能修改自己的额度或该开关。
- 全局页面勾选本次修改的字段，选择仅改默认，或同步允许覆盖用户的已有个人设置。同步恢复所选字段的全局继承，未选字段保留。
- 预览令牌绑定策略 revision、所选字段、生效方式、同步方式、UTC 日期和用户配置指纹；过期预览不能保存，切换生效方式后需重新预览。新增受限人数按预览时的用量和占位计算。

每日训练次数、推理请求、推理输入及累计训练时长下调提供两种方式：默认在下一次 UTC 00:00 重置后生效，也可选择「强制立即生效（仅限新提交）」。上调立即生效；默认方式保留当天已授予额度，强制方式以新目标替换所选字段的当天有效额度，次日均使用最后保存的配置目标。个人设置、全局继承和批量同步遵守相同规则，个人保护与同步授权继续有效，新注册用户直接采用当前配置目标。非每日额度沿用原有规则。

个人额度 PATCH、全局预览 POST 和全局保存 PATCH 接受可选字段 `daily_reduction_mode`，值为 `next_reset`（默认）或 `immediate`，非法值返回 HTTP 400。该字段仅控制本次涉及的每日额度，不写入额度配置或科学实验配置。已有待生效额度可以不修改数字而提前执行：个人页面的「立即应用待生效额度」一次处理当前待生效字段并保留原继承来源；全局页面勾选字段、选择立即生效，再预览保存。未选字段的待生效状态继续保留。

已用额度与占位不会因下调而清零、截断或退还。例如已用 8、额度从 10 强制降至 5，保留已用 8，剩余为 0，后续提交受限；已接收的任务继续沿用原快照。接口数字字段表示当前有效额度，`configured` 表示配置目标，`pending` 给出生效值及时间，`enforcement` 标识管理员豁免。界面将生效时间转换为本地时间，实际变更始终保留后台记录；提前执行同一目标值也记录生效方式与有效额度变化。

个人额度 PATCH、全局预览 POST 和全局保存 PATCH 接受可选布尔字段 `publish_announcements`，默认 `false`，非法类型返回 HTTP 400。管理员每次保存或提前应用待生效额度时可独立勾选推送；成功后选项恢复关闭。仅向实际发生额度变化的用户发布定向公告，重复执行和无变化操作不重复通知。全局预览显示通知人数，预览令牌同时绑定本次推送选择；修改选择后需重新预览。是否推送不影响额度、生效时间、使用记录或已接收任务快照，也不写入科学配置。审计保留本次选择；选择推送时，公告与变更一起成功或回滚。历史公告和已读记录保留，不自动补发或撤回。

模型上限从 5 调为 2 时，已有 5 个模型继续保留，现存模型与任务占位合计少于 2 才能新增；降低保护上限也不会撤销已有保护。页面中性说明当前上限和已有用量，历史合法使用不标为违规。存储及其他个人上限调整限制后续新增，不改写历史使用记录。

实验、集成、Agent 批量实验、恢复训练和推理在接收事务内保存额度快照。已排队或运行的任务沿用接收时额度完成检查、执行和发布；新提交采用当时有效额度。平台级保护仍执行，失败或中断的结果保持未完成状态。快照独立于实验配置和科学内容身份保存。

其他新部署默认值：每日 10 次训练、1 个在途实验（排队＋运行）、每日训练 7200 秒、单次 3600 秒、每日推理 200 次／10000 条输入、单文件 1 GiB、单模型产物 2 GiB、个人存储 10 GiB、模型闲置保留 14 天。每日公开注册上限为 10，队列容量 100，推理超时 300 秒。升级保留原有配置；新增模型总数上限如小于旧保护额度，会相应提高以兼容旧值。

训练提交成功即计每日次数，删除不返还；排队不计时，准备、执行和发布计入运行时长。失败或取消保留已消耗时长，跨 UTC 午夜分摊到各天。推理先占位，保存结果后结算，失败或取消释放占位。推理次数、输入条数、GPU 占用和请求频率限制分别提示；正数每日额度不足时返回下一次 UTC 重置时间，界面转换为本地时间。额度为 0 时提示尚未开放，不承诺次日恢复。公开注册计成功创建的账号，包括未验证账号；初始管理员不占公开注册名额。

## 调度与磁盘保护

同一运行目录只有一个调度器，使用数据库持久队列并按用户轮转。GPU 训练与 GPU 推理使用进程间互斥锁；纯 CPU 经典模型及其集成使用独立 CPU 推理进程。推理超时终止对应工作进程，训练开始前释放暖 GPU 推理进程。

资源策略独立于实验配置，不改写训练命令、随机种子、数据划分、epochs、batch size、精度、语义选项、模型选择与评估。资源不足时拒绝、排队或标记未完成，不缩减训练后冒充完整结果。CLI 及版本内容身份算法保持原行为。

PostgreSQL 行锁和 SQLite IMMEDIATE 事务保证检查、批量创建、计额及队列提交一起成功或回滚；注册邮件在事务提交后发送。用户存储按所属文件逻辑大小计额，同一内容对象在同一用户名下计一次。操作系统的物理空闲空间单独展示，CoW 文件系统下二者可能不同。

上传、快照和工作副本复制前预留空间，盘点完成前继续计入已完成写入。默认空闲少于 `max(10 GiB, 10% 卷容量)` 时暂停新增，少于 `max(2 GiB, 2%)` 时停止增长任务。运行时检查产物、日志及个人存储。应用层监控不等于文件系统硬配额，需要严格物理上限时使用容量受限的数据卷。远程预训练模型标识需管理员允许，已有本地资源保留原路径和格式。

## 定期清理与公告

自动清理默认关闭。「允许定期清理未保护模型及其权重」需**单独启用**；升级前已开启缓存清理的实例不会自动获得删除模型的权限。关闭任一清理开关会取消待执行模型清理计划；再次启用后重新检查到期与保护条件，是否发送清理预告仍由管理员选择。

缓存清理评估可重建推理副本及无引用的废弃临时／工作目录。模型清理评估已完成版本封存、用户所属、未保护且超过个人闲置保留期的模型。**静默模式不增加额外等待期**：符合条件的资源在本次手动清理或后台检查中直接执行清理。模型和临时目录原有的闲置保留期限继续有效，直接调用清理接口也不能绕过。保护或使用模型会取消待执行计划并重新计算闲置期。

清理策略 `retention.publish_announcements` 默认 `false`，控制后台定时任务为新计划发布公告。手动「清理到期资源」通过 `POST /api/admin/resources/retention` 的可选布尔字段 `publish_announcements` 独立选择本次是否推送，省略时为 `false`，不改写定时任务设置。选择发送预告时，`notice_hours` 仅作为公告提前量，至少为 **72 小时**；界面只在选择推送时显示该设置。已经发布公告的计划始终遵守原截止时间，后续关闭推送也不会提前删除；通知不要求用户已读。

计划起点 `scheduled_at` 与实际公告时间 `notified_at` 独立保存。新静默计划的 `delete_after` 等于计划建立时间，意图持久化后在同一轮执行；旧静默计划在下一次检查中取消额外等待并重新核对条件，不因后来选择推送而补发公告。手动清理单个符合条件的资源也无需先建立等待计划。审计记录新计划及旧静默截止时间的调整，失败重试和名额结算遵循原有规则。

清理预览只显示所属用户、状态、截止时间、跳过原因和预计可回收逻辑大小，不删除文件。执行时加锁重新核对所属用户、保护状态、使用时间、在途任务、推理／下载租约、共享引用和内容完整性，并在删权重前核验保留输入。外部路径、显式排除目录、数据集、源码与环境记录及预训练资源不属于模型删除范围。Linux 可通过 `PEP_RETENTION_EXCLUDED_ROOTS` 设置以冒号分隔的绝对排除路径；Docker 部署还需用持久 Compose 覆盖文件将其传入后端。

模型清理后从有效模型库隐藏，停止推理与权重下载；安全回收其独占的受管模型输出、检查点、成员权重副本、原始产物及推理副本。共享对象在其他有效模型或版本绑定仍使用时继续保留，因此删除一个模型不一定释放很多空间。实验参数、指标、历史版本身份和绑定、推理历史及小型报告继续保留；保留版本记录不代表被删权重仍能下载或重新运行，相关请求返回 HTTP 410。后续仍要使用的模型应提前保护或另外备份。

清理前持久化意图，进程中断后可恢复重试。失败记录释放量为 0，直到清理完成才释放模型名额；成功后重复清理不重复累计释放量。记录的释放空间是操作系统观察到的物理空闲增量，可能与逻辑估算不同。空间不足不会提前执行已公告的计划，无安全可回收文件时暂停新增。

管理员公告支持所有或指定用户、置顶、定时生效及结束、每用户独立已读。清理通知由策略管理，不能通过普通公告接口改写。

## 升级

Alembic `20261107_0014` 增加独立生命周期与权重可用性表；`20261107_0015` 增加每日额度过渡、变更记录和任务接收快照；`20261107_0016` 将清理计划起点与公告时间分离，历史已通知计划回填原起点且不改变截止时间，旧策略默认关闭公告推送。直接初始化数据库也兼容升级。这些迁移不改写实验及版本内容身份。应用初始化时为缺少历史快照的排队任务保存升级时有效额度，并明确标记兼容来源；不推测历史额度。Docker 启动流程自动迁移；裸机部署可执行 `alembic upgrade head`。升级前备份数据库和运行目录，等待运行中任务自然结束后部署，保留排队任务。后台策略持久保存在数据库，调整后无需重启。

取消静默额外等待不需要新增数据库迁移；旧静默计划通过正常清理入口重新检查后执行，应用启动和数据库迁移本身不删除文件。已发布公告的截止时间保持有效。
